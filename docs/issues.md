# 課題台帳 (Issues)

KAME 日本語版の未解決課題を「1 課題＝1 ブロック」で管理する。実験は [experiments.md](experiments.md) と相互参照。

**使い方**
- 新しい症状を見つけたら `ISSUE-NN` を追加（症状 → 証拠 → 根本原因 → 候補手 → 状態）。
- 候補手は優先順で並べる。検証する手は実験台帳に `EXP-NNN` として降ろし、ID を「関連」に記す。
- 実験で分かったことを根本原因・確信度・状態に反映する（PDCA の Act）。

**状態の凡例**: 未着手 / 仮説確定（未検証）/ 対処中 / 検証済み（解消）/ 検証済み（未解消）

## ISSUE-01　開幕の自発話 / 役割ミスマッチ
- **状態**: 検証済み（未解消）— `--moshi_speakers B`（EXP-002）では解消せず。真因は **turn-taking（データ構造）**。
- **確信度**: 高（コードとデータで裏取り＋EXP-002 のマイク対話で実挙動確認）
- **症状**: 接続直後にモデルが自分から話し出す。出題・相槌など「質問者側」の振る舞いをし、答える側になりきれない。
- **証拠**:
  - `main_speaker_streams`（`utils/data.py:9-30`）は `moshi_speakers` 指定話者を生成側（text+8 音声）、相手を入力側（8 音声）に割り当てる。
  - `--moshi_speakers` の既定値は `["A"]`（`finetune.py:90`）。`examples/finetune_j_moshi.sh` は未上書き → モデルは A だけを“自分”として学習。
  - 対話データの話者 A は **99.4%（1989/2000）が口火を切る側**＝質問者/出題者。
  - 例: A「…医学博士でもある漫画家、覚えてる?」(問) → B「うん、手塚治虫だね…」(答)。
  - セッションログ: 開幕「ねえ、C を 3 倍にしたとき…」=出題、後半「…3 つの県ってことだね。ありがとう!」=受け手の相槌 → A の役割と一致。
- **根本原因（更新, EXP-002 後）**:
  - **真因 = turn-taking の precedent 欠如**。全対話が frame 0 から話者発話で始まり、「**冒頭無音・相手が先に話す**」例が学習データに皆無。model=B でも、推論時の「開始時に相手（ユーザ）が無音」が未学習（OOD）なので、既定で喋り出す（学習時は開始時に必ず相手 A が talking だったため「無音→待つ」を学べていない）。
  - 加えて QA 由来の**相互クイズ文体**で、B も「出題/相槌」を学ぶ → 「答える」役になりきれない。
  - （当初仮説）「A=質問者を学習」も一因だが、**主因ではない**（B にしても残ったため）。
  - **話者選択は正しく機能していると検証済み**（EXP-002）：ローカルで `main_speaker_streams` が A/B で別ターゲット（B は冒頭 padding=無音）、本番ログ `main speaker = B`、config.json に記録。→ モデルが学ぶ無音は「相手が喋っている間」限定（P(B=無音|A=talking)）で、推論開幕の「全員無音」が OOD。話者フラグの問題ではない。
- **EXP-002 の実挙動**: 無音中に自発出題／質問に答えず相槌／oracle 非追従／流暢性低下（spkB は e5 より退化）。
- **データ精査（2026-06-30, 5,000 対話集計）**: 開幕話者 A=99.5% / B=0.5%。冒頭無音＝第一語開始が平均 0.26s・p90 0.34s・99.4% が <0.5s（＝**冒頭無音ほぼ無し**）。B 発話開始は平均 6.4s（A を約6秒聞いてから回答）。→「無音始まり・ユーザ先行」の例が precedent として存在しないことを定量確認。
- **影響波及**: turn-taking 不全は oracle 非追従（ISSUE-02）の評価も汚す（そもそも会話のキャッチボールが成立しない）。
- **候補手（優先順, 更新）**:
  1. ★ **冒頭無音＋ユーザ先行をデータに作る**（構造変換, 安価, 再合成不要）：各対話の先頭に両ストリーム無音を K フレーム前置し、oracle 位置もずらす。model=B 維持で「開始は黙る→ユーザが話す→答える」を学ばせる。→ EXP-003 候補
  2. **対話をアシスタント QA 文体に再生成**（内容刷新, 高コスト：Step 02 再生成→再合成→再 tokenize）：相互クイズをやめ「ユーザが問う→アシスタントが簡潔に答える」構造に。流暢性低下の是正も期待。
  3. （済・不十分）`--moshi_speakers B`（EXP-002）。
- **関連**: EXP-002 / ISSUE-02 / memory `kame-trained-as-questioner`

## ISSUE-02　oracle 非追従
- **状態**: 仮説確定（未検証、EXP-003 予定）
- **確信度**: 中〜高（機序は整合的だが実験未検証）
- **症状**: 推論時、本体が oracle の内容（新事実）を使い切れない。oracle に答えを流しても発話に反映されない。
- **根本原因**:
  - **(a) フレーム単位の時間的ズレ** — teacher forcing 下で、相手を聞いている間（listening）は本体テキストのラベルが pad だが oracle には答えが先読み配置、本体が答える間（speaking）はラベルが内容だが oracle はほぼ pad。→「oracle=X だから次に X と言え」をフレーム単位で一度も教えていない。
  - **(b) 暗記ショートカット** — 38k 問×5ep で答えをパラメトリック記憶＋文脈からローカル予測すれば損失が下がる。勾配降下は楽な道を選ぶので oracle の限界価値が低く（=冗長）経路が育たない。augmentation（skip 10–70% 脱落, ±数フレーム shift）が長距離記憶を破壊し当てにならない。
- **推論で破綻する理由**: 推論では (1) 質問が新規で暗記が効かない、(2) 自己生成音声に正解が軌跡上に無い。新事実の唯一の供給源は oracle なのに、その経路が未発達 → 非追従。
- **補足**: `semantic_emb_dropout` は「自分の音声をなぞる楽な道」を塞ぐ補助レバー（有効だが主因ではない）。主因は (a)+(b)。
- **候補手（優先順）**:
  1. ★最重要 oracle を speaking フェーズへ重畳/持続 — イベント終了後も pad にせず、答え区間に oracle を 1 フレーム先行で並べ、フレーム単位で oracle→発話を直接教える。
  2. augmentation 弱化（`oracle_skip_prob` 低減）→ 長距離依存を学習可能に。
  3. 暗記ショートカット抑制（データ多様化・重複除去・過学習抑制）。
  4. (任意) oracle コピーの補助損失で追従を直接教える。
  5. 推論側の lead 回復（oracle を先行させる）で、学習した経路を発火。
- **関連**: EXP-003 / ISSUE-01 / memory `kame-oracle-timing-mismatch`
